# 墨读

TypeScript 实现的私人 TXT 小说阅读器，使用 Node.js 在服务端保存书籍，无新增运行时依赖。

## 运行

需要 Node.js 20.19+ 或 22.12+（与 Vite 7 一致）。

```sh
npm ci
npm run dev
```

开发服务器同时提供书籍 API。需要局域网访问时：

```sh
npm run dev -- --host 0.0.0.0
```

正式运行：

```sh
npm run build
npm start
```

默认监听 `http://127.0.0.1:5174`，可通过 `HOST` 和 `PORT` 修改：

```sh
HOST=0.0.0.0 PORT=3000 npm start
```

每次启动会生成随机访问 token，终端会打印完整的 UI 地址，例如 `http://127.0.0.1:5174/?token=...`，请用这个地址打开页面。也可以通过环境变量设置固定 token：

```sh
BQREAD_TOKEN='your-private-token' npm start
```

`npm run dev` 和 `npm run preview` 使用相同规则。未提供有效 token 的页面、静态资源和 API 请求会返回 `401`。首次使用带 token 的地址访问后，浏览器会保存 HttpOnly 会话 Cookie，刷新页面、导入、导出等操作会自动携带认证。默认随机 token 在重启后更换，需要重新打开终端中的新地址；设置固定 `BQREAD_TOKEN` 后可复用原地址。链接本身包含访问凭证，请妥善保管。

`npm start` 同时提供 `dist` 静态页面与 `/api/books` 接口。使用 Nginx 时，可将全部请求反向代理到这个服务。此版本需要 Node.js 后端，仅部署 `dist` 静态文件无法导入、读取或导出书籍。`npm run preview` 也支持书籍接口，供本地预览。

不想装依赖时，可只把 `dist`、`server`、`server.mjs` 三个文件（目录）拷到目标机器，直接 `node server.mjs`：运行时只用 Node 内置模块，不需要 `node_modules` 或 `package.json`。

也可以直接从 Git 仓库运行，`prepare` 脚本会在安装时自动构建 `dist`：

```sh
npx --yes git+https://gitee.com/MangaQQQ/bqread.git
# 或 GitHub 简写
npx --yes github:<用户名>/<仓库>
```

这种方式需要目标机器有 git、Node 20.19+，首次会安装构建依赖并编译，比拷贝 `dist` 慢。

## 功能与存储

- TXT 文件选择、拖放导入，或直接粘贴小说文本
- UTF-8 和 GB18030 自动识别，文件最大 10 MB
- 自动识别常见中文章节标题，支持目录跳转与键盘左右键翻章
- 三种阅读主题与三档字号
- 搜索书籍、按阅读状态筛选、移除书籍
- 封面右上角提供导出按钮，将上传书籍下载为 UTF-8 TXT（包含正文与章节标题）
- 三本原创短篇样例可直接阅读

上传的书籍保存为 **运行服务的系统用户**主目录下的 `~/.bqread/books/<书籍 ID>.bqr`。书架只读取每本书的摘要。打开书时根据本机保存的进度定位章节，读取当前章及相邻各一章；目录跳转和翻出已加载范围时再读取。超过约 2.4 万个 UTF-16 代码单元的章节会拆成小节，原始 TXT 仍可完整导出。旧版服务端 JSON 书籍首次访问时自动逐本建立索引，新文件写入成功后再移除旧文件。书架在同一服务的浏览器和设备之间共享；本项目没有账号隔离，部署范围应为可信的私人环境。删除书籍会删除对应的服务端文件。可通过 `BQREAD_DATA_DIR` 指定书籍目录，例如：

```sh
BQREAD_DATA_DIR=/path/to/books npm start
```

阅读进度与阅读设置保存在当前浏览器的 `localStorage`。清除浏览器网站数据不会删除服务端书籍，但会清除这台设备上的进度与设置。

旧版 IndexedDB 中的书籍会在打开原来的访问地址时自动迁移到服务端；只有全部书籍上传及阅读进度保存成功后，才清理旧数据库。迁移需要在原浏览器、原网站地址下进行，其他浏览器无法读取旧浏览器的 IndexedDB。迁移失败会保留旧数据，刷新可重试。

## 阅读对话

在阅读页点「对话」，或选中文字后点旁边的「对话」。墨读直接连接支持 **Chat Completions 工具调用**的模型服务，自行执行模型调用和查书循环，无需启动 bqagent。服务端只需三个连接参数：

```sh
BQREAD_AI_BASE_URL='https://api.example.com/v1' \
BQREAD_AI_MODEL='your-model' \
BQREAD_AI_API_KEY='your-api-key' \
npm start
```

`npm run dev` 和 `npm run preview` 使用相同环境变量。`BQREAD_AI_MODEL` 必填；`BQREAD_AI_BASE_URL` 默认是 `https://api.openai.com/v1`，程序在其后追加 `/chat/completions`；无认证的本地模型服务可以省略 `BQREAD_AI_API_KEY`。密钥只在服务端使用。不使用 bqagent 的配置、登录或会话接口，旧的 `BQAGENT_URL`、`BQAGENT_WEBUI_PASSWORD` 不再生效。仅提供 Responses 或 Anthropic Messages 协议的地址不能直接用于此接口。

模型可自主分页读取本书目录、章节原文，搜索整本书的关键词，并调用字数统计工具。工具直接读取现有书库，不生成额外的原文副本，也不接受其他书籍或文件路径。选段由服务端按原文位置核对后提供给模型。右侧面板实时显示实际搜索词、查阅章节、统计操作和每一步的状态；回答完成后，点「查书过程」可回看记录。正文引文必须出现在本轮实际查阅的内容中；模型输出或引文有误时会获得一次修正机会，仍不符合要求则显示具体错误。

问“实际计算这本书有多少字”时，程序会统计导入后保存的完整文本，包括其中原有的章节标题、前言和后记。结果分别给出汉字数、非空白字符数和总字符数，按 Unicode 码点计数；非空白字符数包含标点、字母和数字，汉字按 Unicode `Script=Han` 统计。单章统计只计算该章正文，不把另存的标题重复加进去。统计结果由程序输出，不要求正文引文，也不使用作者在书中声称的字数。

对话历史按书籍 ID 保存在书库的 `chats/` 下。重新打开同一本书即可查看并接着聊；每轮携带最近八轮问答及其中的选段，工具结果只保留在本轮模型上下文中。已有聊天记录可以继续使用，旧 bqagent 会话信息会在下一次保存时移除。点面板顶部的「清理聊天」会取消正在进行的模型请求并清空本书聊天、选段和草稿。移除书籍也会清理该书的聊天记录及旧版本生成的工作区。

单轮对话限时四分钟，并有固定的查阅轮次和内容上限。分页会明确返回后续位置，达到上限或模型输出被截断时会报告未完成，不将部分结果当作完整回答。未配置模型时，阅读和书库功能仍可正常使用。

## 验证

```sh
npm test
npx playwright test
```

浏览器测试使用独立的临时书库，不会改动 `~/.bqread` 中的真实书籍。测试覆盖导入、服务端文件持久化、TXT 导出、旧数据迁移、浏览器数据清除后的书籍保留、目录导航、设置与进度、删除、错误提示及 390px 布局。
